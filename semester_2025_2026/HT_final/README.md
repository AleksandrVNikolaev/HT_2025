# Итоговое задание — ROSREESTR Parser

## Описание  
Проект реализует получение кадастровых данных об участках через локальную утилиту **rosreestr2coord**, 
без обращения напрямую к сайту Росреестра.  
Результаты сохраняются в JSON и доступны для анализа через модуль `data_access.py`.

## Подробное описание проекта

### 1) Общая характеристика проекта
Парсер реализует автоматизированное получение и анализ кадастровых данных о земельных участках. 
В основе решения лежит локальная утилита rosreestr2coord, которая получает сведения о геометрии 
и характеристиках участков из источников Росреестра. Такой подход выбран вместо прямых запросов 
к API pkk.rosreestr.ru, поскольку публичный доступ к нему нестабилен и часто приводит к таймаутам 
и SSL-ошибкам. Использование rosreestr2coord позволило обеспечить устойчивость, автономность 
и возможность локальной обработки без VPN.

### 2) Архитектура проекта и последовательность запуска
Проект построен модульно.  
• `models.py` содержит описание структуры данных класса `Parcel`, где определены поля кадастрового номера, 
адреса, категории, формы собственности, площади, стоимости и даты обновления.  
• `parser_rosreestr.py` взаимодействует с утилитой `rosreestr2coord`, получает файлы `.geojson` и `.kml`, 
извлекает из них ключевые сведения и сохраняет агрегированные результаты в `rosreestr_data.json`. 
Запуск — через **метод класса** `Parser.start()` (см. ниже).  
• `data_access.py` выполняет анализ собранных данных — выводит их в табличной форме с переносом длинных 
строк, рассчитывает **среднюю** и **суммарную** площадь и формирует итоговый отчёт `rosreestr_report.csv` 
для последующей работы в Excel/Google Sheets.

Последовательность работы:  
1) Запустить `parser_rosreestr.py` — сформируются/обновятся файлы `.geojson`/`.kml` и JSON-база.  
2) Запустить `data_access.py` — читается JSON, выводится табличный отчёт и экспортируется `CSV`.

### 3) Полученные результаты
Тест проведен на участках 39:05:030616:111, 39:05:030616:112, 39:05:030616:141, 39:05:030616:142. 
Парсер сохраняет данные в стандартизированные форматы `.geojson`, `.kml`, `.json` и `.csv`, демонстрируя 
полный цикл сетевого взаимодействия, агрегации и аналитики данных.

### 4) Требования к настройке парсера
• Установленные библиотеки: `rosreestr2coord`, `requests`, `charset-normalizer`, `idna`, `urllib3`, `certifi`.  
• Для диагностики дополнительно развёрнут Ubuntu (WSL) и альтернативный сценарий через FastAPI.

### 5) Проблемы и решения
• Сетевая нестабильность публичных API Росреестра — заменено на локальную утилиту `rosreestr2coord`.  
• Ограничения системной среды Linux (PEP 668) — выполнение в виртуальном окружении Windows.  
• Отсутствие некоторых участков в БД (например, `39:05:030616:144`) — корректное предупреждение без остановки.
